# Cambios incompatibles de OpenAPI aceptados (D5, ADR 20261028 de política de contratos).
# scripts/diff-contratos.sh se lo pasa a oasdiff (--err-ignore): una línea "MÉTODO /ruta texto"
# con el texto que reporta oasdiff deja de contar como error. Lo revisa el responsable de
# integración (CODEOWNERS); cada línea nombra su motivo en el comentario anterior.

# DTI-27 ítem 3 (2026-10-29): la spec omitía el body que el servicio siempre exigió y devolvió.
POST /api/personas added required request body
PUT /api/personas/{id} added required request body

# D-32 (#897, 2026-10-29): la base exige descripcion NOT NULL; antes la API la aceptaba vacía.
POST /api/donaciones the request property `descripcion` became required

# #908 (2026-10-29): el padrón llega como multipart/form-data; el body {"path"} permitía leer
# cualquier archivo del contenedor y el front ya mandaba multipart.
POST /api/donantes/archivos added required request body

# HB-18 (DTI-30, 2026-11-09; ADR 20261102 del ciclo de vida de la necesidad, ajuste de la migración):
# la spec omitía el body que el servicio siempre exigió. Ahora lo documenta, con dos reglas nuevas
# que oasdiff no ve porque son condicionales: fechaLimite obligatoria en las EXTRAORDINARIA y
# periodicidad obligatoria en las RECURRENTE. Los consumidores del repo (integration-tests y los
# flujos 2, 4, 8 y 9 de Postman) se migraron en el mismo PR.
POST /api/necesidades added required request body
PUT /api/necesidades/{id} added required request body
